## Agent Brief

**Category:** enhancement
**Summary:** Photographers can upload photos and see thumbnails and previews; clients can view them

**Current behavior:**
The server starts with every storage, delivery and job provider replaced by one that throws `provider is not configured`, so upload, viewing, downloads and background processing all fail with 503. The frontend has no upload screen.

**Desired behavior:**
The storage provider contract (create upload capability, verify object, create view capability, create download capability) has two adapters chosen by configuration: local disk for development and Cloudflare R2 (S3-compatible, presigned URLs) for production. The job service runs inside the backend process and processes uploaded originals into thumbnails and previews. The gallery page supports drag-and-drop multi-upload with per-photo progress, failure and retry, plus reorder and delete.

**Key interfaces:**
- `PhotoStorage` provider contract
- `JobService` and the photo-processing job handlers
- Server composition that currently uses the 'unavailable' providers

**Acceptance criteria:**
- [ ] With local storage configured, uploading a JPEG results in a photo with ready thumbnail and preview
- [ ] A failed upload can be retried without re-uploading others
- [ ] Client can view previews of a published gallery
- [ ] Missing storage configuration yields a specific, actionable error, not a generic failure
- [ ] Integration tests run against a fake storage provider

**Out of scope:**
- Zip download
- Deployment to production hosting
- Video support
