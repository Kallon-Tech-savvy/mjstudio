## 5. Surface database errors clearly (pool errors, 503 mapping, startup check)
**Labels:** enhancement, ready-for-agent

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Database failures should be visible and distinguishable from generic server errors

**Current behavior:**
Any database error reaches the client as `INTERNAL_SERVER_ERROR` with no hint, and the pool has no error handler, so a bad connection or missing table is hard to diagnose (this hid the migration failure behind a plain 500). Open PR #1 (first commit) already implements this idea.

**Desired behavior:**
Unexpected pool errors are logged without crashing the process. Database-unavailable conditions map to a 503 with a stable error code. Error logs serialize database error details (code, hint, detail) safely, with secrets redacted. On startup the server checks the database connection and reports a clear message if it fails.

**Key interfaces:**
- A `ServiceUnavailable`-style application error mapped to HTTP 503
- Pool-level `error` event handling
- An error-serialization helper used by the error middleware and the audit logger

**Acceptance criteria:**
- [ ] A simulated connection failure returns 503 with a stable code, not 500
- [ ] A missing-table query logs the Postgres code and hint
- [ ] No connection string or password appears in logs
- [ ] A test covers the 503 mapping and the startup check

**Out of scope:**
- Merging PR #1 wholesale (it also carries an unrelated frontend restructure and deletes a migration; see the reconcile issue)
- Retry/circuit-breaker behavior

## 8. Phase C: show link and PIN once with a share panel (copy, WhatsApp, share sheet) and regenerate
**Labels:** enhancement, ready-for-agent

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Publishing a gallery gives the photographer the client link and PIN to share manually, replacing server-side delivery

**Current behavior:**
Creating gallery access calls a credential-delivery provider that is not configured, so it fails. The server never returns the secret token or PIN to the photographer, so there is nothing to share.

**Desired behavior:**

The UI shows a send panel with separate Copy buttons for link and PIN, a Share on WhatsApp button that opens a prefilled message containing the link, and the native share sheet where supported. Regenerate issues a new link and PIN and invalidates the old ones. Revoke still works.

**Key interfaces:**

- The credential-delivery provider contract (no longer needed for sending)

**Acceptance criteria:**
- [ ] Create access returns link and PIN once; a later GET never returns the PIN
- [ ] Regenerate invalidates the previous link and PIN
- [ ] The WhatsApp button opens a message containing the link; the PIN is not included in that message
- [ ] Integration tests cover create, regenerate, revoke and client verify with the new credentials

**Out of scope:**
- Emailing or messaging from the server
- Hosting/public URL configuration (separate)

## 9. Phase D: real photo storage (local disk + Cloudflare R2), upload UI, previews, job runner

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Photographers can upload photos and see thumbnails and previews; clients can view them

**Current behavior:**
The server starts with every storage, delivery and job provider replaced by one that throws `provider is not configured`, so upload, viewing, downloads and background processing all fail with 503. The frontend has no upload screen.

The gallery page supports drag-and-drop multi-upload with per-photo progress, failure and retry, plus reorder and delete.

**Key interfaces:**

- `JobService` and the photo-processing job handlers
- Server composition that currently uses the 'unavailable' providers

**Acceptance criteria:**

- [ ] A failed upload can be retried without re-uploading others
- [ ] Client can view previews of a published gallery
- [ ] Missing storage configuration yields a specific, actionable error, not a generic failure
- [ ] Integration tests run against a fake storage provider

**Out of scope:**
- Zip download
- Deployment to production hosting
- Video support
